# 통합 채팅 실제 평가 — 2026-09-22

> 이 문서는 당시 평가를 보존합니다. 아래 출력 1,200토큰과 도구 없는 답변의 재시도는 과거 정책입니다. 현재는 출력 650토큰이며 해당 자동 재시도는 제거됐습니다. 최종 상태는 [결정 0036](decisions/0036-final-quality-guards-and-release.md), 현재 구조는 [구조 문서](architecture.md)를 따릅니다.

## 범위와 판정

- 프로젝트: `Room_Reservation/RoomReservation`. 기존 대표 11문장과 변형 4문장, 순차 1회 최종 평가.
- qwen3:8b / qwen3-embedding:0.6b, Top-K 5, 임계값 0.45, 검색 지침 적용 유지.
- 기존 RAG의 서식 포함 근거 문맥 8,000자를 유지했다. 통합 채팅은 별도로 제한된 실제 프로젝트 파일 근거를 결합했다.
- HTTP 성공, 도구 실행 성공, 답변 품질은 서로 다른 지표다.
- PASS: 질문의 핵심에 근거로 답하고 필요한 인용이 의미적으로 연결됨.
- PARTIAL: 유용한 근거/답변이 있지만 인용 누락·범위 부족·일부 미검증 주장이 있음.
- FAIL: 질문 핵심인 현재 구현 상태를 확인하지 않고 높은 완성도를 단정함.
- 수동 검토 결과: **PASS 4 / PARTIAL 10 / FAIL 1**. API는 15/15 HTTP 200,
  모델 응답 상태는 SUCCESS 8 / SUCCESS_WITH_WARNINGS 7이다. 후자를 품질 통과율로 사용하지 않는다.

## 인용과 근거 없는 주장

- 존재하지 않는 인용 ID: 최종 15개 중 0건.
- Knowledge를 조회했으나 인용을 전혀 쓰지 않은 답변: **7개** (#1,2,3,7,8,10,15).
  UI에서 경고를 표시하고 실제 출처 경로/행과 도구 근거를 별도로 제공한다.
- 인용 ID 존재 검사는 의미 검증이 아니다. #4의 README 인용 하나가 코드 클래스 주장까지
  모두 뒷받침하지는 않는다. 이를 PARTIAL로 판정했다.
- #12,13의 인용은 실제 반환된 파일과 주장 연결을 검토했다.
- Git/Workflow 답변에는 toolCalls, toolsUsed, sanitized evidence가 남는다.
- “완료”, “남은 문제 없음”은 작업 목록과 커밋만으로 입증할 수 없다. #1,5,6,14에 문제를 기록했다.
- 모델이 근거를 조회했다고 해서 모든 문장이 근거로 뒷받침되는 것은 아니다. #3의 API 경로 표현,
  #10의 설정값 표현은 특히 검증되지 않은 주장으로 남긴다.
- 초기 개발 검증에서는 Tool 없이 Python/main.py를 지어낸 답변도 있었다. 해당 초안은 최종 기준이 아니다.
  근거 없는 no-tool Project 초안을 버리고 Tool 선택을 한 번만 재시도하는 guard를 추가했다.
  최종 인수인계 응답은 실제 Java/Spring 근거를 조회했다.
  일반 지식의 [GENERAL] 선언은 모델 계약이지 독립적인 의미 검증기는 아니므로 한계가 남는다.

## 실패/지연 관찰 및 처리

- 초기 기본 thinking 상태에서 첫 포괄적 질문가 120초 제한을 넘었다. Unified 호출에만
  thinking OFF와 최대 출력 1,200토큰를 적용했다. 기존 RAG/Agent 호출은 변경하지 않았다.
- 위 변경과 no-tool guard 후 최종 15개를 한 번 평가했다. 최종 개별 시간은 7.116–54.896초.
- 최종 품질을 맞추기 위해 반복 샘플링하거나 prompt/threshold를 계속 조정하지 않았다.
- 추가로 실제 배포 WebView에서 Enter Git 질문 1회: getGitStatus, 약 14.9초, 콘솔 오류 0.
  이 UI 동작 점검는 위 15개 품질 집계에 넣지 않았다.

## 당시 결론

하나의 채팅에서 코드/프로젝트/Git/진행 상태/최근 작업/일반 질문을 처리하는 연결과 한국어 중심 UI는
구현·검증했다. 그러나 인수인계의 상태 근거 수집, 인용 준수와 미완료 판단은 성공 기준을
완전히 충족하지 않는다. **전체 품질 완료 선언은 보류**한다.
당시에는 근거 종류의 충족 여부, 미기록/미확인 상태 표현, 주장별 인용 범위를 남은 문제로 기록했다. 이후 작업과 개발 종료는 후속 결정 기록을 따른다.
Hybrid/reranker/새 모델/새 Tool 추가가 이번 평가의 결론은 아니다.
